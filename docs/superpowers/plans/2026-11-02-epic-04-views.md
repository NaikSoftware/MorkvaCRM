and `…-ux.md` (every visual/interaction number). Read both before any task.

- **Wave A**: Task 0, Task 1+2 (one agent).
- **Wave B**: Task 3 (complete cubit + registry + toolbar slots, so later tasks touch own files).
- **Wave C** (parallel): Tasks 4, 5, 6, 8, 9, 10, 12. Then Task 7 and 11.

Each task branches from the current `worktree-epic-04-views` tip
(`git checkout -B views/<task> worktree-epic-04-views` inside the agent's worktree), commits
there; the controller merges into `worktree-epic-04-views`, runs `flutter analyze` +
`flutter test` after every merge, then deletes the side branch and worktree.

## Rules for every task

- Code discovery: start with `jbcontext search "<descriptive query>"` (narrow with
  `-p <path>`) when you don't yet know the file; switch to direct reads/exact grep once you do.
  The index holds `main` only — code added on this epic branch (`lib/core/domain/view/`,
  `lib/features/views/`) is found by direct reads.

- BLoC, dumb widgets, tokens from `lib/design/tokens`, reuse `lib/design/components`
  (`empty_state.dart`, `PressableScale`, buttons). Material Symbols / `Icons` only, no emoji.
- TDD for logic; widget tests for every new screen/widget.
- Done per task: `flutter analyze` clean, `flutter test` green, commits
  `feat(views): …` ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, made
  with `git -c user.name='Nickolay Savchenko' -c user.email=naiksav4enko@gmail.com`.
- Flutter 3.47: `ReorderableListView` → `onReorderItem` (not `onReorder`); never a `ListTile`
  inside a coloured `DecoratedBox` (asserts) — use `Material(color, shape)`.
- UI tasks: render the new screens (golden-free screenshot via a widget test
  `matchesGoldenFile` is NOT wanted; instead run the app on web or capture with
  `tester.binding` + `RepaintBoundary.toImage` into `sdd/shots/<task>/`), open every image,
  compare against the UX spec numbers and fix obvious defects before reporting; state the commit
  SHA the shots were taken from.
- Subscribe to each repository stream once per cubit lifetime (the repository only releases
  subscriptions in `dispose()`).
- No provenance notes (owner, dates, task numbers) in code comments.
- `lib/firebase_options.dart` is gitignored: copy it from `/home/naik/Dev/MorkvaCRM/lib/` if
  missing.

## Task 0 — Token contrast fixes

## Task 1 — View model on the collection
`lib/core/domain/view/`: `ViewDefinition`, `ViewFilter`, `FilterOp`, `ViewSort` (Equatable,
`toJson`/`fromJson`, `copyWith`), mode id constants (`table`, `board`, `list`, `calendar`).
`Collection.views` (+ `copyWith`, `toJson`, `fromJson`, props). `fromJson`: missing/empty →
`[ViewDefinition.defaultFor(fields)]` (id `all`, name "All", table, default `fieldIds` per
spec), then `reconcile(fieldIds)`. Export from `domain.dart`. `CollectionsListCubit
.createCollection` adds a "Name" text field. Tests: JSON round-trip, legacy doc without views,
reconcile, default fieldIds, editor save keeps views.

## Task 2 — Query core (pure Dart)
`lib/core/domain/view/view_query.dart` (+ helpers): `operatorsFor(field)`, `matches`,
`applyView`, `groupableFields`, `groupObjects`, `bucketByDay`, `formatFieldValue`,
`groupValueFor`, `withDay`, `titleOf`. Semantics exactly as the design spec. Tests: every field
type × operator, sort per type incl. empties, manual order with stale/missing ids, grouping
select/reference/none, day bucketing (UTC stored, local day), formatting per type.
