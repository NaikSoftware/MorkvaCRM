# Module API reference

> Generated by `tool/gen_sdk_types.dart` from `harness.describe` (API 2.0, SDK core 2.0) and the runtime constants. Do not edit; edit the generator.

Start with the [quick start](README.md); the manifest is in [manifest.md](manifest.md) and the TypeScript declarations in [morkva.d.ts](morkva.d.ts).

## The `morkva` object

A module is one classic script. It registers actions at its top level with
`morkva.action(id, handler)`; the runtime then invokes one action per run, in
a fresh sandbox that is thrown away afterwards. Nothing survives between
runs.

| Member | What it does |
|---|---|
| `morkva.action(id, handler)` | Registers an action. Only during the top-level run of the script: later calls are ignored with a warning. `handler(input, ctx)` may return a value or a promise. |
| `morkva.call(op, args?)` | Calls an op (see Operations). Resolves with its result; rejects with a `MorkvaError` whose `code` is one of the error codes. `args` must be a JSON object. |
| `morkva.log(...args)` | A run-log line at level `info`. |
| `morkva.progress({done, total, label?})` | Progress on the pressed button and in the run log. |
| `morkva.version` | The SDK core version, `"2.0"`. |

`morkva` is frozen. The only other globals you can rely on are the ES2020
built-ins (`Intl` is **not** guaranteed), `console` (`log`, `info`, `warn`,
`error`, `debug`, all written to the run log) and `setTimeout` /
`clearTimeout`. There is no `setInterval`, no network (`fetch`,
`XMLHttpRequest`, `WebSocket` are gone), no `importScripts`, no `import()`,
no `eval` or `new Function`, and no WebAssembly. Whatever else a given
engine happens to have may be missing on the next one.

### Return value

- A string becomes the run summary shown in the finish message and the run
  log (cut to 200 characters with "…").
- `{message, ...}`: `message` is the summary; the other keys are kept in the
  run log when they fit in 4 KB. A value over 16 KB keeps only the summary.
- Anything else: the app writes the summary itself ("3 cards updated", "No
  changes").
- A return value that is not JSON, or is over 900 KB, is dropped with a
  warning.

The return value is never written anywhere: changes happen only through
plan ops. Summaries, progress labels and log lines are plain text everywhere.

### Plans

Plan ops (`cards.create`, `cards.update`, `cards.delete`, `fields.*`,
`collections.*` writes, `views.*`) change nothing when called: each adds
items to the run's one plan and resolves with `{status: "planned", planId,
itemCount, summary}`. When the action returns, the runtime seals the plan
and either applies it at once or shows it for review (see the apply policy
in [manifest.md](manifest.md#apply-policy)). So:

- A run's reads do not see its own planned changes.
- Any plan call that fails (other than `no_change`) fails the whole run
  `plan_refused` and nothing is applied, **even if the action caught the
  error**. Check before you plan; `no_change` is safe to catch.
- A run that planned nothing succeeds with "No changes".
- A plan holds at most 500 items.
- Calls the action did not await still join the plan, as long as they
  finish within 2 s of the action returning.

### Trigger time and execution time

`ctx.card` and `trigger.before` / `trigger.after` are the card as it was
when the trigger fired. Your `morkva.call` reads see the data as it is when
the action runs, which can be later when runs queue up. An update planned on
a stale assumption fails the commit's stale check for that card instead of
overwriting a newer change.

### What fires an event

- Only writes made in this app on this device: changes from other devices or
  the Firebase console fire nothing.
- An offline delete, or a change whose save is confirmed only after the app
  restarts, fires nothing; one confirmed later in the same session fires
  late.
- A calculated value changing because another card changed is not an event.
- Deleting a collection fires no `card.deleted`.
- A failed save fires nothing; undo fires nothing.

### Screen refs

The harness ops accept `@card`, `@selected`, `"from": "@screen"` and
`{"screen": true}` for what is on the user's screen. A module has no screen:
these fail `invalid_args`. Use the ids in `ctx`.

## Error codes

`e.code` of a rejected `morkva.call`. An error the action throws (or lets through) fails the run `module_error` with its message: its `code` is not kept.

| Code | Meaning |
|---|---|
| `required` | A required field would be left empty. |
| `out_of_range` | A number or date is outside what the field allows. |
| `too_long` | Text is longer than the field allows. |
| `invalid_option` | The value is not one of the select field's options. |
| `invalid_reference` | A link points at a card that doesn't exist or isn't in the linked collection. |
| `too_many_references` | More links than the field allows. |
| `too_many_files` | More files than the field allows. |
| `invalid_extension` | A file type the field doesn't accept. |
| `invalid_args` | The arguments don't match the op's schema (see `details`), the call was malformed, the args were not JSON (refused inside the sandbox), or a screen ref (`@card`, `@selected`, `@screen`) was used: a module has no screen. |
| `no_change` | The plan call would change nothing. Not a failure: the promise rejects, but the run is not failed and nothing is recorded. |
| `unsupported_version` | The request asked for an API version the app lacks. |
| `unknown_op` | No op has this id. |
| `not_permitted` | The module lacks the capability, the op is reserved to the runtime (`plans.*`, `journal.*`, `modules.*`, `automations.*`, `runs.*`), or "Collection not available to this module": the collection does not exist or is outside the consent. The two cases read the same on purpose. |
| `wrong_type` | A value has the wrong type for its field. |
| `unknown_collection` | Never reaches a module: the runtime reports it as `not_permitted`. |
| `unknown_field` | No field with this id or name (see `candidates`). |
| `unknown_view` | No view with this id or name. |
| `unknown_option` | No select option with this id or label. |
| `unknown_object` | No card with this id or title. |
| `ambiguous_reference` | A name or title matches more than one item; retry with an id from `candidates`. |
| `invalid_filter` | A filter's operator or operand does not fit the field. |
| `read_only_field` | The field is calculated or an auto-number. |
| `type_locked` | The field's type cannot change. |
| `schema_invalid` | The planned schema would be invalid. |
| `formula_error` | A formula does not parse or reads a missing field. |
| `formula_cycle` | Formulas would depend on each other in a loop. |
| `count_mismatch` | `expectedCount` differs from the cards the filter matched. |
| `last_view` | A collection keeps at least one view. |
| `limit_exceeded` | A size or rate limit was hit (see Limits). |
| `plan_expired` | The sealed plan expired before it was applied. |
| `stale_preview` | The data changed after the preview was built. |
| `offline` | Applying needs a connection. |
| `conflict` | The card changed elsewhere since it was read. |
| `unsupported` | The op cannot do this here. |
| `internal` | A bug in the app. The module sees "Internal error"; the full text is only in the run log. |
| `dead` | Not an op error: the run ended (stopped, timed out, failed) while the call was pending. |

## Run outcomes

A run ends `succeeded`, `awaiting_review`, `failed`, `timed_out`, `skipped`, `rejected` or `expired`. The reason codes the run log shows:

| Reason | Meaning |
|---|---|
| `needs_consent` | Skipped or rejected: no consent, the code changed since consent, or the consent was revoked. |
| `broken` | Skipped: the manifest no longer parses, or the automation refers to a field, collection, action or module that is gone. |
| `crashed` | The page stopped while this ran (probably out of memory); the automation is paused. |
| `paused` | Skipped: the automation is turned off. |
| `loop_suspected` | Skipped: the automation was paused for running too often in a chain. |
| `engine_unavailable` | Skipped: this device cannot run modules. |
| `not_settled` | Skipped: the change did not reach the local data within 5 s. |
| `not_permitted` | The trigger collection is outside the effective grants. |
| `loop` | Skipped: the automation is already in this chain of runs. |
| `depth_limit` | Skipped: the chain of runs is deeper than 3. |
| `fan_out` | Skipped: one commit started more than 100 runs of it. |
| `queue_full` | Skipped: too many runs were waiting. |
| `review_backlog` | Skipped: 50 runs already wait for review. |
| `card_gone` | Skipped: the card was deleted. |
| `cancelled` | Stopped by the user. |
| `duplicate` | Skipped: this change already started this automation. |
| `load_error` | The module threw while loading, or does not register the action. |
| `boot_error` | The sandbox failed to start. |
| `load_timeout` | The module did not register its actions within 5 s. |
| `module_error` | The action threw or rejected (the message and stack). |
| `plan_refused` | A plan call failed (other than `no_change`), even if the action caught the error, or sealing the plan failed. Nothing is applied. |
| `abuse` | The sandbox broke the frame protocol or its rate. |
| `limit_exceeded` | A run limit was hit, or on Android/iOS JS ran for more than 1 s without awaiting. |
| `offline` | An auto-apply needed a connection. |
| `not_applied` | The changes were not applied. |
| `interrupted` | The app closed while the run was applying. |
| `internal` | A bug in the app. |
| `code_changed` | Rejected: the module's code changed before review. |
| `uninstalled` | Rejected: the module was uninstalled. |
| `superseded` | Expired: the run was started again. |

## Limits

| Limit | Value | When it is hit |
|---|---|---|
| Run time | 20 s, `timeoutMs` 1–60 s | The run is stopped: `timed_out`. Nothing is applied. |
| Start-up | 5 s from start to registered actions | `failed: load_timeout`. |
| Busy JS without `await` | 1 s | Android/iOS: `failed: limit_exceeded`; try/catch cannot catch it. Web lets it run to the run time. Split long loops with `await`. |
| Memory | 64 MiB on Android/iOS | An "out of memory" error the action may catch; uncaught it fails `module_error`. Web uses the browser tab's own limit. |
| Calls per run | 500 | The next call is refused and the run fails `limit_exceeded`. |
| Calls waiting for an answer | 8 | Refused `limit_exceeded` (a refused plan call fails the run). |
| Heavy reads at once (`cards.query`, `cards.aggregate`) | 2 | Queued, not refused. |
| Arguments of one call | 256 KB of JSON | Refused `limit_exceeded`. |
| Arguments per run | 2 MB of JSON | The run fails `limit_exceeded`. |
| Time spent in ops per run | 5 s | The run fails `limit_exceeded`. |
| Log lines | 500 per run, 500 chars each, 50 arguments | Longer lines are cut; extra lines are dropped and counted. |
| Progress | 10 per second, label 60 chars | Extra updates are dropped. |
| Timers | 100 pending, delay at most 60 s and the run's time left | `setTimeout` throws `RangeError`. Timers die with the run. |
| Messages to the app | 2000 per second, 1 MB each, JSON depth 64 | The sandbox is killed: `failed: abuse`. |
| Plan items | 500 | The run fails `limit_exceeded`. |
| Return value | 16 KB (900 KB inside the sandbox) | Only the summary is kept (over 900 KB: dropped). |
| Auto-apply | 20 low-risk card creates/updates per run; 1000 items per workspace per 10 min | The plan waits for review instead. |
| Chains of runs | Depth 3; 100 runs per automation per commit; 30 chained runs per automation (120 per workspace) per 60 s | Skipped (`depth_limit`, `fan_out`); the breaker pauses the automation (`loop_suspected`). |
| Queue | 100 runs per automation, 500 per workspace; one run at a time | `skipped: queue_full`. |

## Engines

The same module runs on two engines; write for the intersection.

| | Web | Android / iOS |
|---|---|---|
| Sandbox | A Web Worker in a sandboxed iframe with a strict CSP | QuickJS in its own isolate |
| Busy JS over 1 s | Runs until the run time | Interrupted: `limit_exceeded` (not catchable; `finally` does not run) |
| Memory | The browser's limit | 64 MiB; going over is a catchable "out of memory" error |
| Unhandled rejection | Logged as an error line | Not logged |
| `Intl` | Present | Missing |
| Stack traces | `morkva-module/<id>.js` file names | QuickJS form |

A throw inside a `setTimeout` callback logs "Uncaught …" and fails the
running action `module_error` on both engines.
